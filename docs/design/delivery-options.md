# 交付形式：文件夹工具包与单一入口

状态：用户已确认文件夹组织及 `BOOTSTRAP.md` 入口，并进一步要求实现 GitHub 远程获取；细节继续迭代。

## 当前决定

工具包组织为独立的 `agent-project-bootstrap/` 文件夹。主要使用方式是提供其 GitHub 入口链接和目标项目位置，由首个 Agent 固定完整 SHA 后读取同提交的入口及依赖；完整本地文件夹/ZIP 是离线备用。

入口按阶段调用项目识别、记忆生成和 Git 协议，使用随包模板生成目标项目的短入口与长期文件。后续 Agent 从目标项目自身恢复工作，不需要原工具包。

## 三个层次

| 层次 | 形式 | 原因 |
| --- | --- | --- |
| 本项目的设计材料 | 多个 Markdown | 支持共同讨论、审查和维护 |
| 初始化交付物 | GitHub 远程读取或本地文件夹，唯一入口 `BOOTSTRAP.md` | 统一协调，按阶段读取，不需要逐份投喂 |
| 目标项目的长期记忆 | 短 AGENTS、上下文、任务与详细协议 | 减少常驻上下文，独立于工具包 |

## 使用边界

- 工具包不是已安装的 Skill，没有自动发现或自动执行机制；必须显式启动。
- 用户只需指定入口；远程模式需联网读取完整正文，本地模式需取得完整文件夹，两种模式都需能修改目标项目。
- 远程来源固定完整 SHA，后续模块不得混用移动分支/tag；获取公开协议不授权上传目标项目。
- 模板使用 `.md.template` 后缀，生成到目标项目后才成为 `.md`，防止模板被误当作活动指令。
- 默认首次执行；再次执行采用审计、补缺或明确升级，不覆盖项目特定规则。
- Git 是工具包内部模块及目标项目的按需协议，不要求用户额外执行第二套 Git Prompt。
- 单文件便携版和特定 Agent 的 Skill 适配暂不交付，未来有实际需求再增加。

## 历史取舍

此前曾建议默认单文件交付。讨论后，为按需加载、独立维护和统一入口选择文件夹方式，见 [交付决策](../decisions/ADR-20261003-folder-delivery.md)。
