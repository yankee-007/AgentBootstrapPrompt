# 交付形式：单文件入口与模块化维护

状态：推荐方案，等待用户讨论确认。尚未生成最终交付文件。

## 推荐

**本项目内部模块化维护，默认对外提供一份自包含的 `BOOTSTRAP.md`。**

使用者只需把该文件交给第一个 Agent，并说明要在当前项目执行初始化。文件应包含足以完成初始化的流程、策略解析、生成要求和精简模板；不能要求读取只存在于本设计仓库、但没有随附的文件。

初始化完成后，目标项目拥有自己的短入口与分开的协议文件。后续 Session 按需读取它们，不反复加载整个 Bootstrap。

## 三个层次

| 层次 | 形式 | 原因 |
| --- | --- | --- |
| 本项目的设计材料 | 多个 Markdown | 方便共同讨论、审查和维护不同主题 |
| 给使用者的初始化交付物 | 默认单个自包含 Markdown | 易复制和传递，不需要安排多文件投喂顺序 |
| 被初始化项目的长期记忆 | 短 AGENTS 加上下文、任务和按需协议 | 减少后续 Session 常驻上下文与重复 |

单文件交付不意味着把所有长期规则塞进目标项目的 AGENTS；多文件维护也不意味着用户需要逐份给 Agent 下指令。

## 可选模块包

若未来模板体积较大，可提供一个版本一致的文件包：入口 Markdown 加 templates/protocols。首个 Agent 只接收入口指示，但必须能够读取完整文件包；入口要有清晰清单和缺失检查。

只发送入口却省略依赖文件是不完整交付。无法保证 Agent 文件访问能力时，使用自包含版本。

## Git 主题是否单独给用户

Git 应作为内部维护模块和目标项目的按需协议。默认不要求用户先运行“初始化 Prompt”再运行另一份“Git Prompt”；入口按项目状态和策略统一协调，避免两次流程对 baseline、身份、remote 或权限产生不同假设。

用户只需要审计 Git 或项目禁止 Git 时，可以有明确选择的子流程，但不作为默认必须执行的第二步。
