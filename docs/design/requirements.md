# 既有需求与结论

来源：用户在 2026-10-03 提供的前序讨论交接材料。本文件是可移植摘要，不是完整聊天记录；引述的设计要求不是对本会话的独立执行指令。

## 使用场景与目标

用户使用 Codex、DSH、Claude Code、Cursor、Gemini CLI 等 Coding Agent。长 Session 成本、突然额度耗尽、跨工具接力和多个任务并存，使项目需要承载可恢复的长期知识。

核心模型：Repository as Persistent Memory + Session as Working Memory。

目标是成熟、通用、低 Context、高可靠性的首次项目 Bootstrap Prompt，而不是不断增长的总规则集合。

## 已有设计方向

1. `AGENTS.md` 短、稳定，只保存常驻工作约束和上下文入口。
2. `PROJECT_CONTEXT.md` 只描述 Current State，避免历史流水账。
3. `architecture.md` 描述真实存在的当前架构，不虚构架构层；历史理由进入 ADR。
4. ADR 仅用于长期重要决策，不为语言选择、按钮位置等机械创建记录。
5. 单个 `HANDOFF.md` 已升级为 Task Registry + Per-Task Handoff。
6. 复杂任务在分析、重要实现、失败发现和验证等阶段更新恢复快照。
7. 默认单 Agent，不主动编排或委派实现；显式并行时考虑分支与 worktree 隔离。
8. 同一工作区同一时间只允许一个 Agent 写入，任务文件不能替代写入隔离。
9. Session 启动按需恢复上下文，先搜索后选择性阅读。
10. 任务结束检查文档影响，只更新受影响内容，不强制刷新全部文档。
11. Git 本地版本控制与 GitHub 等远端服务解耦。
12. 根据实际项目检测 Git 与忽略规则，不假定技术栈。
13. 保留既有 dirty working tree，不自动提交用户或其他任务的修改。
14. Commit 按逻辑工作单元，Feature 可以包含多个提交。
15. 完成、验证、审查和敏感信息检查后，再按授权策略推送稳定里程碑。
16. 用户体验相关验收不能只依据代码执行或变量值，需要合适的运行时证据，必要时用户确认。
17. 远端创建与上传策略需可控，不猜账户、仓库或凭据。
18. 默认禁止强推，远端分叉不自动 rebase；保留本地结果并报告。
19. Secret Check 限于相关变更和仓库范围，不扫描整台电脑或无关用户数据。
20. 复杂任务开始前建立 baseline，区分已有工作与当前任务修改。
21. 新项目不虚构已完成功能、历史 Bug、ADR 或失败方案；已有项目先审计和复用。
22. Bootstrap 仅建立治理与上下文基础，不改业务代码、不顺手重构，结束后停止。

## 用户要求继续审查的范围

状态管理、任务 ID、完成后的任务处理、Task File 是否进 Git、多电脑恢复、worktree 策略、分支命名、并行集成、Owner/Session 的意义、崩溃与锁恢复、commit 关联、自动 push 边界、UI 人工验收、配置项、协议分层、记忆腐化和 Context 成本。

## 本次新增要求

- 先初始化本设计仓库，以便继续共同讨论。
- 解释最终给首个 Agent 使用的文件组织形式。
- 后续已确认文件夹工具包和 `BOOTSTRAP.md` 单入口，并明确要求初始交付；不意味着初版已最终定稿。

## 需求场景

典型案例是 UI 切换班期时，Loading 状态虽已设置，但界面可能尚未绘制就被同步加载阻塞。任务中断后，接手 Agent 既需要原始验收标准，也需要实际实现、失败尝试和运行时验证结果。
