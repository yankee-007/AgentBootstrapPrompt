三个 GPT-6 Luna 子 Agent 均采用 low，使用独立夹具；维护仓库保持一个写入者。原始产物与报告只保留本地，此处保存可移植的核验摘要。

| 执行 | 实际结果与证据 | 适用限制 |
| --- | --- | --- |
| 首轮生成 small / partial | 小项目职责合并、部分治理补缺、disabled 跟踪/提交/远端、同文件 staged/unstaged 与未跟踪用户内容；最终链接和语义复核通过，partial 重跑未重复追加 | 经维护 Agent 指出遗漏后修复，不能记成无指导首次通过 |
| 新上下文 regression | Git/跟踪/提交/远端 disabled 均保留；补缺时已有策略、工作流完整原段保留，README/NOTES 原文保留；未创建 .git/Task/活动表，重跑不重复追加 | 无业务代码，未运行应用检查；没有覆盖全部取值 |
| 新上下文接手 handoff | 只获目标入口和 Task ID，未读工具包；识别实际代码已折叠空白而旧快照声称尚未处理，补齐非字符串 TypeError；4 项 unittest 通过，维护 Agent 的 10 个独立边界用例通过 | 首次索引收尾失败，需指导后复核；修改前恢复摘要的输出时序未独立确认 |

首轮具体失败：覆盖了 partial 已有未跟踪 policy/workflow 后依据先前原文恢复；索引误放根目录、职责合并后遗留旧架构链接；workflow 重复追加、遗漏崩溃前收尾限制及 Git fetch/敏感范围义务；报告曾写入未经核实的哈希片段，后以真实查询修正。维护 Agent 据此增加局部补缺/原文比对、默认保留规范正文和 Git 最低语义。后续新上下文 regression 的原段保留检查通过；这不抹除首次失败。

接手夹具的首次收尾将活动表行改为 done 而未删行，独立检查判定未满足完成标准。维护 Agent 补强工具包的收尾顺序和最终 ID 核对，并要求按目标已有协议修正。最终独立复核：原 Task 路径保留、ID 已从活动表移除，NOTES 字节与未跟踪状态不变，10 个边界用例仍通过。最后这项措辞强化的模板增补按静态方式核验，不宣称已无指导重测所有场景。
