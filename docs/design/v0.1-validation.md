## 协议场景静态审查

以下是逐项阅读规则的覆盖审查，不是环境故障注入或端到端运行结果。

| 场景 | 协议应有的行为 | 规则位置 |
| --- | --- | --- |
| 空项目、没有业务架构 | 未知信息明确标注，不虚构模块、ADR、任务或验证 | discovery、memory |
| 已有规范与重复初始化 | 映射复用、最小补缺，保留现有策略 | discovery、memory |
| monorepo、submodule、worktree | 识别实际根与授权范围，不误建嵌套 Git | discovery、初始化 Git |
| 既有 staged/unstaged/untracked 内容 | 核对整个待提交快照，不清理或顺带提交用户工作 | discovery、目标 Git |
| 无 Git、无身份、无网络 | 保留已完成文档或本地提交，分别报告结果 | 初始化 Git |
| 缺模板或目标不明确 | 阻塞相关步骤，具体报告缺项，不凭空补写 | BOOTSTRAP |
| 秘密曾出现于历史提交 | 检查此次上传历史，不仅看当前 diff | 目标 Git |
| 多 push URL、远端分叉、推送竞争 | 核对全部实际目标，不自动重写或强推 | 目标 Git |
| 突然中断、任务记录落后 | 重要阶段保存，接手者核对实际文件与 Git | workflow |
| 跨电脑或不能上传 | 交接可取得的代码与环境；允许受控离线方式，不把文档当备份 | workflow、目标 Git |
| 多 Agent 与陈旧 Owner | 默认单写入者；按需隔离，共享资源另协调 | workflow、目标 Git |
| Registry 分支视图与 ID 冲突 | 标明可见范围，随机 ID 与碰撞检查，索引可修复 | workflow |
| UI 体验与人工验收 | 证据覆盖实际表现，验收绑定版本，待验收不冒充 done | workflow |
| 模板被自动发现、工具包被移走 | `.md.template` 不作为入口；生成文件仅引用目标项目 | README、memory、目标模板 |
| 完成记录与最新 commit 循环 | 通过 Task ID 和 Git 查询，不为写最新 hash 重复提交 | workflow |
