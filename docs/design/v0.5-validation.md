# v0.5.0 核验记录

日期：2026-10-16（Asia/Shanghai）。范围为本仓库 Markdown 工具包与生成规则；关联 [任务](../tasks/TASK-20261016-a7c392e6b501-v05-risk-driven-execution.md)。

## 版本与范围

v0.5.0 分两个逻辑单元实现按需观测和轻量执行路径，不开发第三阶段自适应隔离。保留 adaptive 跟踪、task-worktree、串行 squash、重要阶段保存及授权边界。工具包增加 1 份按需观测模板，共 18 个文件；默认项目不生成观测报告，也不新增普通 Session 必读文件。

本记录区分结构检查、模板实例化检查、规则场景审查与实际运行实验。规则存在不等于 Agent 一定遵守；未运行 20 对真实开发任务，不报告性能提升、完成率或跨 Agent 安全验收。

## 文档与模板检查

检查对象为本任务分支的 v0.5.0 内容，主线集成后的适用性另行核对。已执行的检查：

- 首轮结构检查覆盖当前修改文档及包内文档共 19 个非模板文件，连同两组实例化结果共检查 160 个相对链接，无缺失；入口清单覆盖 4 份协议与 11 份模板，共 15 项依赖，工具包总数 18。
- 临时目录内按模板直接实例化“观测未启用”和“观测已启用”两种项目：分别生成 9 和 10 个文件，均无残留占位符或失效相对链接；前者不含观测文件，后者包含。未实例化虚假 Task。此检查只验证模板组装，不作为真实 Agent 自动初始化的证据。
- 核对版本入口/说明/策略来源均为 0.5.0；0.4.0 引用只用于历史或升级背景。差异格式检查通过；原有最低语义及本轮新增义务的持有位置见下表，未为了快速路径删除已有跟踪、保护、保存或集成义务。
- 实例化结果不含包内协议/模板路径或远程包读取要求；明确启用的夹具在策略依据中记录采样范围，未启用的夹具不生成观测文件。对本轮 21 个拟上传变更文件作有限凭据模式检查，未发现匹配；此结论不代表不存在任何形式的敏感信息。

## 场景规则审查

以下为对规范文本的静态推演，未启动额外 Agent 或把它们执行为真实开发任务：

| 场景 | v0.5.0 规定的行为 | 规则位置 |
| --- | --- | --- |
| 用户称“只改一个按钮” | 先有限只读侦察，不据描述假设低风险；新独立任务仍按 task-worktree 隔离 | workflow：开始、最小路径 |
| 同一任务补充、修正或换 Session | 核对实际文件、写入者及快照后复用原任务/工作区；没有 Task 文件时查分支/摘要 | workflow：开始、最小路径；git：工作区 |
| 两个文件增至三个 | 文件数本身不触发记录、隔离或验证升级 | workflow：风险变化 |
| 发现共享接口、迁移或权限影响 | 分别补充调查、记录/恢复及相应行为检查；既有隔离工作区通常复用 | workflow：风险变化、验证 |
| always 跟踪下的小任务 | 保留真实 Task，不能由快速路径豁免 | policy：策略条件；workflow：开始 |
| disabled 跟踪下扩大风险 | 不强制创建/更新 Task/活动表，仍保护文件、按风险检查并说明恢复限制 | policy：策略条件；workflow：风险变化 |
| 项目明确 single-writer | 只有有效策略允许且确认单写入者、归属与恢复边界时才可共享目录串行写入 | workflow：最小路径；git：工作区 |
| 项目 follow-existing 但具体边界未知 | 查明项目规则，不推断允许共享写入或自动放宽 | workflow：最小路径；policy：策略解释 |
| 原工作区有混合修改，需要迁移 | 先保存、停写、核对；不能分离则暂停相关迁移，保留现场 | workflow：风险变化；git：工作区 |
| 侦察遇到安装、生成、迁移命令 | 侦察保持只读，实施和环境准备须在有效写入边界内另行安排 | workflow：最小路径 |
| 同内容、环境、检查证据未失效 | 可引用复用，不机械重跑无关全量检查；必检及最终内容核对仍执行 | workflow：验证；git：集成 |
| 集成目标/依赖变化或冲突处理 | 重新判断旧证据适用范围，相关部分重验，不能仅凭无文本冲突宣告正确 | workflow：验证、集成；git：集成 |
| 观测未启用 | 不读取观测模板正文、不生成空报告，不强制 Task；未来采样规则已在 workflow 内 | memory：输出映射、检查；workflow：观测 |
| 显式采样且 Task disabled | 用分支或样本 ID 关联独立观测，仍不更新 Task/活动表，不自动上传 | policy、workflow：观测；观测模板 |
| 缺打点、跨 Session 或并行重叠 | 未测记未知，阶段不重复相加；保留间隔/覆盖缺口，无数据不报提速 | workflow：观测；观测模板 |
| Worktree 快但依赖准备慢 | Git 工作区与依赖/环境单列，记录缓存、返工、等待和模型/工具不可拆分限制 | 观测模板：计时口径 |
| 请求推送未验收内容 | 可按授权备份整个项目；质量、Task 完成与集成条件分别判断，不扩大 refs | policy、workflow、git |

审查结果：以上场景的预期边界在当前模板正文中均有对应条款；这仅说明文本覆盖，没有证明实际 Agent 的执行率或故障恢复能力。

## 最低语义与来源独立性

| 新增/相关义务 | 目标项目中的持有位置 |
| --- | --- |
| 短入口、任务定位、按需读取 | `AGENTS.md`；`docs/agent/workflow.md` 的开始与最小路径 |
| 跟踪、隔离、提交、上传和集成的独立条件 | `docs/agent/policy.md` 的有效策略及冲突表；Git 协议 |
| 有限只读侦察、任务/环境复用、风险信号及安全迁移 | workflow 的最小路径、风险变化；Git 的任务工作区 |
| 针对性验证、证据复用和失效后的重验 | workflow 的验证；Git 的串行集成 |
| 观测默认不采样、阶段口径、未知和质量结果 | workflow 的执行观测；明确采样时的独立记录 |
| 任务身份、状态、最小快照、checkpoint、索引与完成 | workflow 原有章节及任务模板/索引，未因本轮精简删除 |
| 用户修改、敏感内容、多工作区备份、squash 清理 | policy、Git 和 workflow 原有保护/授权边界，仍适用 |

以上路径可在小项目中映射到等价章节。观测未启用时，目标 workflow 已持有未来记录样本的最低字段、计时口径和对比方法，无需重新联网取模板；明确采样时才按需建立记录。

## 未验证与后续评估

- 尚无 20 对真实开发任务的 v0.4/v0.5 对比；本轮自身的前置读取/工作区阶段没有连续计时，不能事后冒充性能样本。
- 原有修改保护、跨 Session 恢复、越权和集成错误需结合真实任务/实验记录；本轮静态场景不代替这些运行证据。
- 尚未实际验证多 Agent 同时写入、竞争集成、随机崩溃或跨电脑接力。本轮按项目要求由单 Agent 完成，工具包无执行层锁。
- 自适应隔离未实现也未启用；先采样、定位瓶颈，再决定是否需要第三阶段，不凭观察结果自动修改项目策略。
