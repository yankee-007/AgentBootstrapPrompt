# 项目记忆与协作体系：多角度优化分析与接手清单

记录日期：2026-10-04（Asia/Shanghai）。对象：已初步完成的体系及 v0.2.0 初始化工具包。

本文件完整整理本轮可恢复的多角度分析要点，关联第一轮审查和 Luna 实验，而不保存私有对话全文。用户本轮明确要求保存分析以便接手；这不表示已接受全部建议，也不授权实施全部优化或上传远端。下列优先级、实施顺序和验收办法均为 Agent 建议。

## 接手摘要

当前方案的主线可继续使用：文件夹工具包、单一 BOOTSTRAP 入口、按需读取、目标项目独立持有长期规则、任务快照与 Git 实际状态核对。已确认的产品形态无需从零重建。

最主要的实际发现是：初始化 Agent 可能在“适配小项目”时丢掉关键协议，导致模板有要求而生成结果没有要求。Luna 受控接力成功，尚不能证明普通任务会自发及时落盘或随机中断后可靠恢复。建议先保证最低语义保留，再优化篇幅与配置，最后扩展故障场景。

开始接手时读本项目入口、上下文、策略及 [当前任务](../tasks/TASK-20261003-5de5ecfa19b3-bootstrap-prompt-design.md)，核对当前 Git 与已有修改，再按条目读取相关文件。不要为理解本清单加载全部历史或再次 Bootstrap 本仓库。

## 优化条目

### OPT-01 · P0 · 生成适配的最低语义保留

**角度与问题**：执行可靠性。允许按项目改写模板，但没有清晰定义不可裁剪内容。Luna 将目标 workflow 压缩成三段，遗漏任务字段、随机 ID、状态枚举、更新时间与完成索引规则。

**建议**：区分必须保留的行为约束和可缩短的说明/示例。最低要求覆盖任务身份、需求与完成标准、原有修改边界、当前快照、验证证据、下一步和交付限制；具体最低集合待讨论。Bootstrap 收尾检查生成文档的语义覆盖。

**状态/位置**：实测发现，改进待讨论；核查 `agent-project-bootstrap/protocols/memory.md`、`BOOTSTRAP.md` 与 workflow/Task 模板。

**验收建议**：不同规模夹具生成后逐项核对最低要求；允许篇幅不同，但不得通过删除关键义务实现轻量化。

### OPT-02 · P1 · 默认上下文成本

**角度与问题**：使用成本。AGENTS、PROJECT_CONTEXT、policy 加任务等必读内容可能形成固定开销；存在按需读取原则，尚无真实读取量和恢复成本基线。

**建议**：让入口只保存稳定约束与导航；上下文只保存当前摘要；policy 保存有效取值；详细协议在相应操作前读取。减少重复表达，记录必读文件规模与实际读取范围。

**状态/位置**：已有按需加载规则，成本测量待验证；核查入口、上下文与策略模板。

**验收建议**：比较小项目与复杂项目启动/恢复的阅读范围，同时确认不会为了减量漏读授权和用户修改边界。未测量前不宣称节省具体 token 比例。

### OPT-03 · P1 · 小项目治理规模

**角度与问题**：适用性。小项目也默认生成多份治理文件；复杂 Task 自适应并不等于整个文件体系足够轻。

**建议**：讨论轻量模式，允许复用等价文档或合并职责，保留明确路径映射与独立恢复能力。不要先增加更多模式开关。

**状态/位置**：工具包已允许短内容和复用等价文件；文件数量/模式改进待讨论，见 memory 与 discovery 协议。

**验收建议**：小项目无需维护空洞重复文档；项目扩大后能补足职责而不覆盖原有规则。

### OPT-04 · P0 · 恢复前的简短事实摘要

**角度与问题**：可观察性。接手者被要求核对实际状态，但没有明确、简短的恢复输出契约；容易把旧任务记载当事实。

**建议**：在接手的重要修改前说明恢复出的目标、完成标准、当前进度、验证缺口、用户修改边界及快照偏差；信息充分时继续，不把这一步变成默认等待批准。

**状态/位置**：核对要求已存在；本次 B 在外部实验指示下成功回报摘要，不能当作协议已自发触发的证明。可讨论写入 workflow 模板。

**验收建议**：只给 Task ID；在任务快照落后于代码时仍能识别偏差，明确未知而不虚构需求。

### OPT-05 · P0 · 脏工作区基线与归属

**角度与问题**：数据保护。任务可能记录 HEAD，却遗漏 staged、unstaged、untracked 或同文件混合修改；按文件暂存也可能混入用户内容。

**建议**：保留开始时相关修改边界，在提交前核对完整暂存快照；同文件无法安全区分时保留成果并说明具体困难。区分用户内容与本任务产生内容，避免复制无关敏感 diff。

**状态/位置**：Git 与任务模板已有要求；本次仅实测保护一份独立未暂存 NOTES，其他情况待验证。

**验收建议**：分别测试用户已暂存内容、未跟踪文件、同文件混合修改；禁止以成功保护 NOTES 推断这些场景已通过。

### OPT-06 · P0 · 配置冲突与关闭跟踪

**角度与问题**：协议一致性。policy 允许 TASK_TRACKING_POLICY=disabled，而工作协议仍可能用无条件语句要求复杂任务建记录；其他开关也存在覆盖与优先级问题。

**建议**：使相关义务明确受有效策略约束；列出少量必要冲突规则，例如 disabled 远端覆盖自动推送，禁止提交覆盖恢复提交。关闭 Task 时明示恢复能力下降及剩余交接方式，不继续承诺完整恢复。

**状态/位置**：policy 已有部分优先级和能力下降说明；跨文档一致性待核验，核查 policy、workflow、Git 模板。不是已实测失败。

**验收建议**：静态检查关键组合，再用关闭 Task/提交/远端的夹具观察真实动作，不静默改成宽松值。

### OPT-07 · P0 · 上传授权的持续范围

**角度与问题**：权限。一次交付授权可能被后续 Agent 当作永久自动推送授权；remote、登录能力和以前成功推送均不能证明本次授权。

**建议**：授权记录清楚说明目标、分支、内容范围、适用任务/阶段和已知副作用；已有适用授权不重复询问，历史授权不自动延伸。

**状态/位置**：本仓库已明确历史交付授权不涵盖后续上传；工具包已有范围记录，持续适用性的表达仍可审查。核查 policy/Git 模板及本仓库对应协议。

**验收建议**：新 Session 能正确区分已授权里程碑与后来新增内容；验证 remote 存在但无授权时的行为。

### OPT-08 · P0 · Bootstrap 部分完成与恢复

**角度与问题**：故障恢复。初始化写到一半、网络读取失败或提交条件缺失时，文件存在不等于初始化完成；再次执行可能重置策略或重复追加。

**建议**：明确检查和补缺步骤，报告已完成、未完成、未知及阻碍；仅在完成检查满足时报告 Bootstrap 完成。是否需要独立状态标记待讨论，避免无必要新增锁文件或后台机制。

**状态/位置**：memory 已有从现有内容补缺、重跑不重置规则；完成状态表达和中断行为待验证。

**验收建议**：在生成中途停止后重跑，既有用户文档与策略保持，缺项补齐，失败结果不伪装成功。

### OPT-09 · P1 · 事实来源、假设与时效

**角度与问题**：记忆可信度。Agent 推断可能写成确定事实，Git 状态、验证结果和已批准决定可能过期。

**建议**：重要结论保留足够证据/核验范围，未知信息直接标记；检查时间与对应版本放任务或验证记录，长期上下文避免重复易变 Git 信息。无需给所有句子增加繁重来源标签。

**状态/位置**：已有事实/推断分离要求；统一程度待审查，核查 Task、上下文、架构及验证记录。

**验收建议**：更换实现后不沿用过期测试/人工接受结论；不能因无回复而登记批准。

### OPT-10 · P1 · 多分支文档的语义集成

**角度与问题**：协作集成。Markdown 没有文本冲突仍可能产生重复任务、过时上下文、互斥策略和双重完成状态。

**建议**：一个集成执行者核对任务 ID、策略、活动索引和当前架构的一致性，在合并结果验证行为；任务索引可重建，不能当全局调度或锁。

**状态/位置**：workflow 已有串行集成和语义冲突说明；真实并行/合并待验证。默认仍单 Agent，不自动引入编排系统。

**验收建议**：两分支修改相关记忆、无文本冲突的夹具也能发现含义冲突；共享端口、数据库、Git 设置等资源另行隔离。

### OPT-11 · P1 · 不同 Agent 的入口激活

**角度与问题**：跨工具兼容。AGENTS 文件可读不等于所有工具都自动加载；过度绑定私有会话或复制多套规则会造成漂移。

**建议**：共享规则保持通用，只在明确需要时生成薄适配入口；无法证实自动加载时给出显式读取方法，并报告核验范围。

**状态/位置**：已有薄入口原则；本次子代理被明确要求读项目文件，未验证自动发现。平台适配尚未全面实测。

**验收建议**：至少分别观察显式读取与自动加载，不将同一宿主的空历史子代理等同于独立产品/新进程。

### OPT-12 · P1 · 固定版本与稳定交付

**角度与问题**：发布维护。main 随时间变化；固定 SHA 能保证一次执行一致，但用户还需知道稳定版本、升级与旧目标项目的关系。

**建议**：继续保持同仓库同 SHA 依赖；讨论稳定版本入口、变更说明与明确升级方式，已有目标项目不自动重跑。新版本需有自己的固定引用，不能继续宣称旧引用包含新内容。

**状态/位置**：v0.2.0 固定来源已核验；稳定发布/升级体验待讨论，核查 source 协议和工具包 README。

**验收建议**：main 变化时一次执行不混版本；离线包与固定版本相符；旧项目仍独立运行。

### OPT-13 · P0 · 真实中断与跨电脑代码可取得性

**角度与问题**：交接保证。文档保存、本地代码保存、其他电脑取得代码是不同事实。协议不能保证崩溃前执行收尾。

**建议**：重要阶段落盘，接手按真实差异恢复；跨电脑明确可取得的代码快照、未包含文件、环境与下一步，无法上传时使用允许的离线方式。

**状态/位置**：已有规则；Luna 实验只证明显式检查点后的同机接力。随机中断、额度耗尽、跨电脑仍未执行。

**验收建议**：先取消显式 checkpoint 提醒，再测快照落后；跨电脑实验另行确认代码传输，不能仅传 Task 文件。

### OPT-14 · P1 · 验证覆盖与完成措辞

**角度与问题**：质量判断。有限测试通过被说成“没有验证缺口”，实现、测试、人工接受、提交、推送、合并被混成 done。

**建议**：结果绑定实际检查范围、版本和限制，分别报告交付事实；UI 时序/体感需适当运行证据，不能用单截图替代。人工接受是否必要由实际验收标准决定。

**状态/位置**：状态分离和 UI 证据规则已存在；B 的“无遗留验证缺口”措辞过宽，独立 12 项验收补充覆盖后通过。

**验收建议**：有未验证边界时明确列出范围；不要求每项都等用户批准，也不把有限自动测试当全面保证。

### OPT-15 · P1 · 任务字段、状态和索引生命周期

**角度与问题**：可维护性。ID、更新时间、状态不一致会削弱恢复，已完成任务留在活动表会形成歧义。

**建议**：启用 Task 后保留一致的最低字段；接力沿用 ID，完成任务保留文件并移出活动表，索引落后时按文件和实际状态修复。

**状态/位置**：模板已有规则，Luna 生成结果遗漏并导致索引不一致；与 OPT-01 同属下一轮重点，不重复设计一套状态系统。

**验收建议**：初始化生成协议和后续实际 Task 都核对；不只检查模板文本存在。

### OPT-16 · P2 · 文档长期增长与职责漂移

**角度与问题**：维护成本。任务变聊天流水账，入口/上下文/架构重复，建议未经审核写成有效规则，低价值 ADR 膨胀。

**建议**：任务保留最新快照和关键依据，稳定职责各归其位；仅更新受影响文件。优化建议集中跟踪，重要长期取舍形成后才建 ADR；不要为了记录最新 commit 再制造一轮收尾提交。

**状态/位置**：已有规则；本文件补上遗漏的分析导航。任务是否归档及何时压缩需随规模讨论。

**验收建议**：下个 Agent 能从少量入口找到当前工作和待定项，不需要私有聊天或全量历史。

### OPT-17 · P0 · 来源信任、秘密与远端暴露

**角度与问题**：安全边界。公开工具包来源不代表可上传目标项目；外部文本不能扩权；首次 push 会暴露历史而不只是当前 diff。

**建议**：保持来源/目标分离、固定路径和权限边界；检查本次新暴露的历史，凭据及无关个人数据不入项目记忆。能力与授权分别判断。

**状态/位置**：第一轮审查及 source/Git 协议已有要求；真实含敏感历史、越界依赖、无权限等行为测试未全面执行。

**验收建议**：使用无真实秘密的夹具验证边界，报告扫描范围，不以“扫描未发现”保证绝无秘密。

## 建议实施顺序与接手动作

1. 优先讨论 OPT-01/15 的最小保留要求，并一起核对 OPT-04/06/08。建议在一个小版本内修复生成规则与完成检查，具体范围待用户指示。
2. 再处理 OPT-02/03 的轻量化及 OPT-07/09/12 的可维护性，避免轻量化重新删除必要行为约束。
3. 用 OPT-05/10/11/13/14/17 扩展运行验证；每个实验明确输入条件、判定标准、实测结果和局限。没有实验不登记通过。
4. 后续落实时逐项记录对应文件、验证证据及处理状态；当前没有任何条目因“已保存”而被视为用户批准或实施完成。

本轮交付是分析和交接记录。工具包仍为 v0.2.0，没有依据此清单自动修改协议、执行新实验或上传。整体迭代任务保持 active；接手者按用户下一项指示继续。
