# Luna 本地中断接力实验

日期：2026-10-04（Asia/Shanghai）。结论：本次受控检查点接力通过；发现生成协议的信息保留问题。不是全场景验收，也不表示方案已定稿。

## 实验条件

- 用户指定使用 GPT-6 Luna 子代理。准备、实现 A、接手 B 的创建配置均为 `gpt-6-luna`，使用 `fork_turns=none`，未继承父会话历史；模型名称依据调用配置，不以代理自述作为独立后端证明。
- 本地实验目录为桌面的 `bootstrap-handoff-lab`。同机、同一工作区、串行写入；协调者确认 A 停止后才启动 B。未创建 GitHub 仓库或配置 remote。
- 准备代理从固定提交 `fa82217e7506d654fa8373ae192898d4756334d7` 的远程入口执行 v0.2.0 Bootstrap，建立 Python 标准库 CSV 示例及项目记忆。
- 基线为 `d9fa90e5c66bfc6e41655e3a87832883adc8c564`，分支 `main`，原有 2 项测试。实验最终复核环境为 Python 3.14.6。
- Task Tracking 为 adaptive；自动提交、恢复提交、自动推送、远端均 disabled。准备阶段单独授权建立种子和治理文档的本地提交。
- 干净基线后，协调者在 `NOTES.md` 加入明确属于用户的未提交备注；随后未改写代理产生的协议、任务、实现或测试。

## 任务与流程

任务是在保持 `parse_students` 行为的前提下新增 `import_students`：要求 name/email 表头，清理首尾空白，按 empty_name、invalid_email、duplicate_email 顺序拒绝；邮箱恰有一个 @、两侧非空且不含空白，允许 a@b；只对已接受邮箱忽略大小写去重；保持输出顺序、首次邮箱大小写和数据行号。空白 CSV 记录及多行字段不在本次范围。

1. A 收到完整需求，但阶段限于实现、运行旧测试、保存任务检查点；明确要求暂不新增测试、不得关闭任务。
2. A 建立 `docs/tasks/HANDOFF-20261004-01.md`，记录需求、用户修改、实现进度及下一步。旧 2 项测试通过后发送 `CHECKPOINT_READY` 并等待。
3. 协调者调用中断工具，返回 A 此前处于 running；之后才启动 B。这是预先约定检查点的中断，未模拟随机崩溃或断电。
4. B 仅收到项目路径、Task ID 及通用恢复/完成指示，未收到原始功能需求、A 的回报或独立验收脚本。
5. B 修改前回报了完整业务规则、实现已完成但缺新测试、基线与用户备注边界，均与实际文件吻合；随后增加测试并更新文档。
6. B 结束后，协调者复跑项目测试及事先存于实验目录外的独立验收，未向 B 提供失败提示或补丁。

## 发现与待审核建议

### 生成适配可能丢失关键协议

准备代理将目标 `docs/agent/workflow.md` 压缩成三段，未保留模板中的任务最小字段、随机 ID、状态枚举、带时区更新时间、完成任务移出活动表等要求。A 因此采用了 `HANDOFF-20261004-01`，任务文件没有明确更新时间和标准状态字段。B 的任务索引一面写“当前无已登记活动任务”，一面在“活动任务”表保留已完成行。

这是本次生成结果与模板之间的可观察差异。尚不能将原因全部归于模型：工具包允许“按项目改写”和“小项目可以很短”，但未明确压缩时不可丢失哪些语义。

建议下一版区分可裁剪说明和必须保留的行为约束，在 Bootstrap 收尾时核验生成文档的语义覆盖，而不只检查文件、链接和占位符。轻量项目可减少篇幅，但仍需定义启用 Task 后的最小恢复信息。

### 成功存在实验条件支持

A 被明确要求保存检查点，B 被明确要求先恢复再工作；这些外部实验指示补足了一部分生成协议的薄弱处。因此本次证明的是“给定检查点能否完成接力”，不能证明 Agent 在普通任务中会自发及时落盘。

B 报告“无遗留验证缺口”，但其 5 个新增测试未单独覆盖若干边界，例如空姓名与已接受重复邮箱同时出现；独立验收补充覆盖后通过。建议结果措辞绑定具体检查范围，避免把有限测试表述为不存在缺口。

### 后续实验建议（未执行）

1. 先明确生成协议不可丢失的最小要求，再重复本实验比较生成结果。
2. 取消 A 的显式检查点提醒，在任务文档落后于代码时中断，观察 B 能否识别差异。
3. 增加用户已暂存修改、未跟踪文件、基线已有测试失败等独立场景。
4. 另测新会话进程、不同模型及跨电脑恢复。跨电脑时必须另行提供完整代码快照与环境，本实验的本地未提交状态不足以支持它。
