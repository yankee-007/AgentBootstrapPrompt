# 设计、迭代与交接协议

按当前阶段读取本协议，修改前至少覆盖开始、最小执行路径与验证；跟踪、接力、集成、完成或观测触发时补读相应章节。只跳过已确认不适用的正文，不绕过项目必读和有效义务。

## 开始

1. 阅读有效指令、项目上下文和项目策略。
2. 有 Task ID 时直接读取对应文件；否则从任务索引定位。
3. 核对当前文件、分支、HEAD、暂存区、未暂存和未跟踪内容。
4. 只读取本次讨论涉及的设计材料；引用材料中的指令按历史背景处理。

接手已有任务的重要修改前简述目标与完成标准、实际进度、验证缺口、用户修改边界及任务快照偏差；信息充分时继续，关键未知只阻塞相关动作，不默认等待重复批准。

独立修改任务按 Git 协议先建立唯一任务分支/worktree，即使只有一个 Session；澄清、修正和接力沿用原任务，不按消息或 Session 新建。讨论、查询和只读审查通常无需新建；复杂任务继续使用任务文件，轻量任务可用分支和交付摘要追溯。main 只接收成果，不在其中开始开发。

## 最小必要执行路径

接收需求后先进行有限只读侦察：搜索相关文档/实现、直接影响和检查入口，核对任务身份、有效策略、Git 与用户修改边界；信息足以确定写入边界和必要检查时开始实施，不默认读全部历史或单独写侦察报告。侦察不执行安装、生成或其他写文件命令。

已有任务先核对分支/worktree、旧写入者已停止及快照偏差后复用；无 Task 文件的任务按唯一分支和交付摘要定位，main 空索引不等于没有其他任务。新独立修改继续先建分支/worktree，再实施、按风险验证并按策略保存/集成/交付。备份、功能完成、人工接受与集成分别判断。

同一 Session 未变化规则只按需补读，可用环境不重复初始化，不为轻量任务运行无关构建或安装；项目必读与必检仍保留。关键 Git 写入、交接或外部变更时刷新必要状态，不能用先前读过文档代替当前写入权核对。本仓库保持 task-worktree；其他项目只有有效策略明确允许共享目录串行写入时才可采用，不能由 Agent 判断任务小而放宽。

共享接口、数据迁移、权限/敏感数据、并发冲突或难恢复修改等实际信号出现时，分别补充调查、记录、检查和必要隔离；不依据文件数量、用户说“小改动”或预估时长机械升级。复杂、跨阶段、易中断或需接力时补建/更新 Task，跟踪关闭则不写 Task 而说明恢复限制。已有隔离工作区通常复用；需迁移时先保存、停写、核对 staged/unstaged/untracked 及必要忽略文件，归属不清不强制迁移或清理，只暂停受影响操作。

## 任务记录

- 跨 Session 的设计或迭代工作维护同一个 Task ID，换 Agent 不新建同一任务。
- 无外部任务 ID 时采用 `TASK-<YYYYMMDD>-<12位随机十六进制>`，创建时检查可见冲突。
- 工作状态使用 planned、active、verifying、awaiting_acceptance、done、cancelled；阻碍另行记录并保留所处阶段。
- 在需求澄清、重要设计修改、关键验证及交接时更新任务快照。
- 区分用户已确认结论和 Agent 建议；不把无回复视为批准。
- 原始需求保存足够准确的脱敏摘要，避免私有聊天流水账。

## 验证

- 检查 Markdown 相对链接、文件职责、重复和冲突规则。
- 检查是否把待审核建议写成已决定、把计划写成已完成。
- 检查目标项目示例是否自包含，是否误引用本设计仓库。
- 以当前工具包版本为对象，按相关故障场景验证覆盖情况；区分静态审查与实际执行证据，不将初步完成视为全部场景通过。
- 无必要不安装工具、不建立构建系统、不添加只复述文档内容的测试。
- 先按影响范围选择最小充分检查；项目必检仍执行。共享规则、接口或恢复边界变化时扩大相关覆盖，轻量路径不等于免检。
- 相同内容/环境且仍有效的证据可以注明依据后复用；实现、环境、依赖、验收项或集成基线变化导致失效时重验相关部分。最终集成内容及含义仍需核对，不为阶段变化机械重复全量检查。

## 执行观测（按需）

默认不采样；用户或有效项目约定显式选择任务/窗口后才记录，复用阶段切换，不逐工具打点、不强制建 Task 或空报告。跟踪关闭时用分支/样本 ID 关联独立观测记录，不维护 Task/活动表；记录位置与范围在项目策略中说明，保存/上传仍按既有授权。

样本包含需求与风险、协议版本、实现起点/成果、Agent/模型（可取得时）、环境/缓存、带时区的起止时间与交付边界；按秒记录读取、侦察、工作区、依赖/环境、实施、验证、集成/交付及观测记录成本。等待/中断、未分类与并发重叠单列；同一区间不重复相加，集成后检查归集成。未执行记 0、未测量记未知，不追造计时前的耗时或宿主未提供的模型/工具细分数据。自然总耗时与扣除已知等待后的耗时分开，记录跨 Session 间隔与覆盖缺口。

同时记录完成、行为检查覆盖、用户修改保护、实际接力证据、越权提交与集成错误。需要对比时先约定成功标准，建议对覆盖文案、样式、局部逻辑、共享组件、接口与跨模块的 20 个真实任务，从相同实现基线在独立可恢复副本中配对执行原版/优化版，交替顺序、说明环境与缓存干扰，比较阶段分布、配对差值、中位数与范围。不能配对时只作描述性观察；未验证质量不记通过，不以提速抵消修改丢失或错误集成，不凭数据自动切换隔离策略。

## 交接与完成

- Task File 是上次核验的快照，不是工作区锁，也不是代码备份。
- 接手者核对真实文件与 Git 状态，发现偏差后先恢复事实。
- 同机交接先停止旧写入者；跨电脑交接同时提供可取得的代码版本和环境恢复说明。
- 工作完成、验证、用户验收、提交、推送分别报告。
- 用户要求推送时按 Git 协议保存整个项目当前状态；未完成或未验收内容可以备份，测试和人工验收不作为快照推送门槛，Task 状态仍按完成标准判断。
- Git 事实查询 Git；不要为了把最新 commit hash 或 push 结果写入同一提交而反复提交。
- 完成任务保留文件，移出活动索引；索引落后时根据任务文件修复。
- 文档影响检查只更新受影响内容，ADR 仅用于长期重要取舍。

## 任务隔离与集成

- 各任务可先后开始，独立任务从当时已确认的 main 提交建立工作区；不复制其他任务的未提交修改。依赖任务需说明所需可取得版本与顺序。
- 独立的 B 可在 A 未完成时先集成；A 后完成时与最新 main 协调差异。原目录已有人工作时不切换其分支；迁移前停止旧写入者，保存并核对原有修改。
- 集成由一个执行者串行进行，具体见 Git 协议。无需 main 开发占用标志，但仍须确认集成写入权；Task、Owner、超时或 worktree lock 都不提供互斥。
- 默认达到任务集成条件后 squash，记录任务与主线成果的可核查关联；对话结束、Session 断开或已备份不自动触发集成。检查最终合并内容及文档含义，需求矛盾或重要取舍未知时保留成果并暂停受影响部分。
- 完成并核验后才清理本任务分支/worktree；未完成、待接受、有依赖或未保存内容时保留。任务内部历史如需长期追溯须另保留可取得版本引用，哈希文字和已合并列表不能替代保存核验。
