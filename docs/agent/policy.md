# 本项目策略

协议版本：1。适用范围：本体系与工具包维护仓库。

这些策略落实用户对本项目初始化、讨论及后续维护的要求，不构成其他目标项目的默认配置，也不允许 Agent 自行扩张授权。

| 项目 | 当前策略 |
| --- | --- |
| 工作模式 | 单 Agent；显式要求后才考虑委派或并行 |
| 内容阶段 | 项目记忆与协作体系已初步完成，当前工具包 v0.4.0；仍处于试用、验证与迭代，不再以生成一份最终 Prompt 为目标 |
| 交付 | 2026-10-09 用户取消离线版本，仅通过 GitHub 入口交付；不再生成或维护 ZIP，本项目已生成的交付 ZIP 清理，历史记录保留 |
| Task Tracking | 复杂或跨 Session 工作使用独立任务文件；小改动不强制新建 |
| Git | 本地初始化并保留既有工作 |
| 自动提交 | 日常任务中，归属明确且通过相关检查的逻辑单元可提交；用户要求推送时可直接建立整个项目当前状态的快照提交，不以测试或验收为门槛；使用真实提交身份 |
| 恢复提交 | 需要交接时可在安全范围内保存明确标注的未完成工作，不表示验收完成 |
| 远端 | 已确认目标为 `yankee-007/AgentBootstrapPrompt` 的 `main`；2026-10-09 用户要求以后推送保存整个项目当前状态。收到推送请求后沿用该目标，不按任务重新申请内容授权；不由此新建仓库、强推、改写历史或执行部署 |
| 推送 | 按请求保存项目快照：包含已跟踪文件的当前内容及删除、未忽略的新文件和已有修改，不限于本轮任务。未完成、未测试或未验收内容可保存，如实注明状态；只保留必要的目标/分支与凭据保护检查，不逐文件征求批准 |
| 工作区 | task-worktree：独立修改任务先建立分支与 worktree，即使只有一个 Session；补充与接力沿用原任务，每个工作区一个写入者；讨论/查询通常不建立 |
| 并行 | 默认单 Agent 实施，不因任务隔离自动委派。显式并行时各任务独立工作区，共享资源另协调；2026-10-05 允许的 Luna 低档测试仍仅在独立夹具目录写入 |
| 验收 | 文档结构、链接和一致性由 Agent 检查；方案取舍与最终定稿由用户审核 |
| 集成 | squash-on-completion：main 仅接收成果；本任务执行者协调串行集成，检查目标无其他写入者，不合并未知任务，不引入后台合并/发布服务。提交、必要验收及远端边界仍适用 |
| 清理 | 集成核验后可清理本任务本地 worktree/分支；确认成果、必要历史和忽略内容已保存，无其他任务依赖。远端删除另需授权，未完成任务保留 |

用户名、邮箱、凭据和本机路径不作为可移植协议内容。Git 身份配置只在用户提供信息后写入本仓库，不修改全局配置。

上述推送偏好来自 2026-10-09 用户的明确指示，取代此前按单轮任务限定上传内容的规则；用户随后要求“更新交付”，允许将整个项目当前可纳入 Git 的状态提交并推送至既有仓库 main，包含已有两份说明文档。用户再取消离线版本，本轮继续同步该交付方式调整，不再维护离线包。快照遵循既有忽略规则，不自动强制纳入依赖、缓存或本地敏感配置；备份不改变业务任务完成或验收状态。

2026-10-10 用户讨论任务级分支/worktree、串行集成和 squash 后要求“根据讨论更新交付包”，本轮据此更新默认协议并沿用 GitHub 唯一交付与既有 main 目标。任务分支使用 `codex/` 前缀，不绑定 Session；集成由明确的单一执行者完成，记录/超时不提供互斥。多工作区备份协调各任务写入者；现有上传目标仅 main，未集成任务先保存本地并如实报告远端未覆盖，不为备份提前合入 main 或擅自扩大上传 refs。
