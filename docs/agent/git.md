# 本项目 Git 协议

## 基线与归属

- Git 写操作前确认项目根、当前分支、HEAD、staged、unstaged、untracked 状态。
- 无提交时明确记录 unborn 状态，不虚构 baseline commit。
- 保护已有修改，不自动 reset、clean、stash、改写历史或清理用户暂存区。
- 普通任务按归属明确的文件或修改块暂存，复核 staged 范围；不因内容已暂存而顺带提交范围外修改。
- 用户要求推送整个项目时，该请求包含保存已有修改和必要快照提交；不再逐项按任务归属拆分，也不把用户内容认领为本 Agent 的实现。

## 本地提交

- 使用实际配置或用户提供的身份，不能伪造姓名和邮箱。
- 以逻辑工作单元提交；任务相关提交可在正文引用 Task ID。
- 本项目文档修改按需检查链接与一致性；项目快照提交不以这些检查、业务测试或人工验收通过为前提，未完成与未验证项如实说明。
- 恢复提交明确标注未完成和未验证项，不能等同于最终验收。
- 提交失败保留工作，报告缺失条件；不绕过签名、hook 或权限限制。

## 远端

- 已确认目标为 `https://github.com/yankee-007/AgentBootstrapPrompt.git` 的 `main`，连接沿用同一仓库的配置。2026-10-09 用户要求推送保存整个项目当前状态，取代以前按单轮任务限定内容的上传规则。
- 每次收到“推送/同步项目到 GitHub”等请求，直接按下述项目快照流程处理，不再逐文件确认，也不要求任务先完成。没有推送请求或持续自动推送约定时不自行上传。
- 使用明确目标和当前约定分支；不默认上传全部分支或标签。
- 禁止未获当前操作明确授权的强推、历史重写、分支删除及远端替换。
- push 与部署、发布、合并是不同动作，分别受授权范围约束。

## 项目快照推送

1. 确认当前目录、分支和实际推送目标与既有约定一致，且没有未结束的 merge/rebase 或冲突；无需重新征求同一目标的批准。
2. 纳入项目全部已跟踪文件的当前内容及删除、未忽略的新文件、原有 staged/unstaged 修改。包括项目记忆、已完成任务和原有导读；不按本轮任务筛选。遵循忽略规则，不使用 `git add -f` 强制纳入缓存或本地配置。
3. 对即将纳入的内容作必要的凭据保护检查，发现私钥、token 等具体问题时处理受影响内容。只检查本项目相关内容；已检查并推送到同一目标的历史不反复扫描。
4. 可在确认项目根后使用 `git add -A` 保存整个项目当前状态，使用真实身份建立快照提交；若没有新改动则沿用现有提交。提交说明未完成或未验证状态，无需为备份额外运行测试、构建或等待验收，不绕过既有 hook、签名和权限。
5. 正常推送到已确认目标。远端拒绝、分叉或网络失败时保留本地快照并报告，不用强推覆盖远端；无必要不为推送增加全历史审计。
6. 根据实际 push 结果报告同步情况；备份成功不自动把 Task 标记 done，也不表示部署或验收完成。

## 任务工作区

- 独立修改任务在写入前，从已确认的 main 完整提交建立唯一 `codex/<task-slug>` 分支与 worktree；复用本任务可用工作区，不占用其他任务目录。补充、修正和接力沿用原任务，讨论/查询通常不新建。
- main 仅接收成果；一个工作区一个写入者，不在有人工作的目录切换分支。worktree 不自动复制未提交修改；已有工作迁移先停止写入者、保存并核对归属及必要文件。
- 默认单 Agent；显式并行也需协调共享 Git 设置、数据库、端口、缓存和产物。Task Owner、超时和 `git worktree lock` 不是文件写入锁。
- 无 Git/基线或禁止分支/worktree 时报告限制，不伪造隔离；在允许且确认单写入者的范围内保存文件。初始化文档可在指定目标工作区串行完成，随后停止，不自动迁移任务。

## 串行集成与清理

1. 确认当前任务范围、依赖、检查和必要人工接受已满足，以及提交/集成授权有效；对话结束或备份请求不自动触发合并。
2. 保存并固定任务成果提交；由明确的单一执行者取得 main 集成写入权，检查主工作区干净、无未结束 Git 操作，核对最新 main。未知修改先保护和调查，不擅自清理。
3. 默认 squash 固定任务提交，在最终内容上核对相关行为、链接、任务 ID、策略、索引、上下文和架构，再建立带任务关联的成果提交；任务分支仍可按逻辑单元提交。冲突依据双方需求处理，不机械选边，不重写已共享历史。
4. 确认实际集成结果并交还写入权；失败保留任务与现场。独立任务可先集成，依赖任务按明确顺序；A 未完成不阻止独立 B，A 后完成时结合最新 main 处理差异。
5. 本任务核验完成后才清理本地分支/worktree；确认写入者停止、无其他任务依赖，未提交/未推送与被忽略的重要内容已保存。需要长期保留过程提交时另留可取得版本引用；远端删除另需明确授权。

squash 形成普通成果提交，不保留任务分支作为 main 的祖先；不能只靠 `git branch --merged` 或 Task 的 done 判断能否删除。清理需核对任务提交、主线成果关联和完整内容；不能因列表未显示就重复合并或强制删除未知工作。普通 merge 能直接接续时可 fast-forward，不要求每任务建立菱形。

## 多工作区项目备份

用户要求整个项目快照时按需核对项目关联 worktree，由各写入者协调保存各任务当前可纳入 Git 的内容；不抢占其他任务暂存区，不在持续写入时捕获混合状态。未完成任务留在任务分支，不为备份提前集成。现有远端授权仅 main：正常同步 main，其他任务先保留本地并说明尚未远端覆盖；需要任务备份 refs 时只澄清缺少的分支范围，不逐文件重复确认，不默认 `push --all`。
