# 本项目 Git 协议

## 基线与归属

- Git 写操作前确认项目根、当前分支、HEAD、staged、unstaged、untracked 状态。
- 无提交时明确记录 unborn 状态，不虚构 baseline commit。
- 保护已有修改，不自动 reset、clean、stash、改写历史或清理用户暂存区。
- 按归属明确的文件或修改块暂存；提交前复核整个 staged 快照。
- 本次任务范围外的内容不得因已经暂存而顺带提交。

## 本地提交

- 使用实际配置或用户提供的身份，不能伪造姓名和邮箱。
- 以逻辑工作单元提交；任务相关提交可在正文引用 Task ID。
- 本项目文档修改需通过链接与一致性检查，并检查 staged 内容中的敏感信息。
- 恢复提交明确标注未完成和未验证项，不能等同于最终验收。
- 提交失败保留工作，报告缺失条件；不绕过签名、hook 或权限限制。

## 远端

- 用户已提供 `https://github.com/yankee-007/AgentBootstrapPrompt.git`，并授权初始化及本次 GitHub 远程工具包交付推送至 `main`。连接使用同一仓库的 SSH 地址；不另建仓库，不扩大到其他分支、部署或服务发布。
- 获授权后核对实际推送 URL、分支和待发送范围，检查此次新暴露的历史内容。
- 按策略 fetch 并判断实际目标分支关系；失败或分叉时保留本地工作并报告。
- 使用明确目标和分支范围；不默认上传全部分支、标签或未知历史。
- 禁止未获当前操作明确授权的强推、历史重写、分支删除及远端替换。
- push 与部署、发布、合并是不同动作，分别受授权范围约束。

## 并行

- 默认一个工作区一个写入者；Task Owner 字段不提供互斥。
- 需要并行时按需使用独立分支和 worktree/clone；不得假设 worktree 复制未提交内容。
- 共享 Git 设置、外部资源、集成和清理需协调；Git worktree lock 不是文件写入锁。
