# 初始化阶段 Git 协议

在任何 Git 写操作前读取；同时读取将应用到目标项目的 `templates/docs/agent/git.md.template`，其中的安全边界同样适用于本次初始化。已有项目使用其实际等价规则。

## 检测与本地准备

- 使用 discovery 阶段基线；每次写操作前复核相关状态未被其他写入者改变。
- 先核对有效策略及覆盖条件；Git 写入、自动提交或远端关闭时只执行仍被允许的部分，恢复提交不能绕过提交禁令。模板默认值不覆盖目标项目的显式 disabled/ask。
- 已有 Git 仓库沿用根、分支和配置，不自动重命名分支、替换 remote 或迁移 VCS。
- 无 Git 且目标边界明确、没有既有禁止/其他 VCS 约定时，可按默认策略在目标根执行初始化。Git 不可用或现有 VCS 需要迁移时，保留文档并报告，不安装工具或擅自迁移。
- detached HEAD、冲突、进行中的 Git 操作或身份缺失时，不擅自修复历史；继续独立的文档工作，提交部分保留待处理。

## 忽略规则

根据真实技术栈、构建配置与既有约定最小补充 `.gitignore`。常见依赖和缓存可以候选排除，但 `dist`、`build`、测试数据、锁文件或 vendored 内容在某些项目中需要跟踪，不能机械忽略。

保留必要的示例配置。工具包若置于目标内，是否纳入版本控制需按用途明确处理，不能顺手提交整个工具包或忽略用户原有内容。机器特定临时文件可使用本地排除机制，但不能因此隐藏应交付的项目记忆。

忽略规则不影响已经跟踪的文件，不自动执行取消跟踪或删除。发现已提交秘密时阻止相关上传、说明范围；轮换凭据或改写历史是另外的明确操作。

## 初始提交

- 本次可提交的只有归属清楚、通过检查的初始化内容；既有无 Git 项目中的业务文件也不自动属于本次提交。
- 全部 staged 内容必须核对；用户预先暂存的其他内容不能被带入，也不能被擅自移除。
- 使用实际 Git 身份或用户提供的信息，不猜邮箱或修改全局身份。
- 提交前执行文档影响、差异格式、路径范围与敏感信息检查。若检查失败，修复本次内容或说明具体阻碍。
- 不要求为取得 baseline 而先提交整个目录，不使用无范围的 `git add .`。

## 可选远端

目标不存在或授权不明确时，仅说明本地结果及需要的目标信息。远端存在不代表允许上传；认证能力与上传授权分别检查。

用户明确选择自动创建私有仓库时，还必须已确定服务、账号/组织、仓库名、可见性和内容范围；通过可用认证创建后核验结果，不猜账户、不索要聊天中的 token、不覆盖已有 remote。

配置和推送遵循目标 Git 协议，检查实际 URL/分支、待发送历史和分支关系。不要为试权限而执行上传，不自动建立 SSH、安装客户端或修改机器全局配置。

无网络、无认证、无提交身份、远端被拒绝或分叉时，分别报告本地文档、本地提交和远端同步结果；不得以 GitHub 失败宣称所有本地工作失败，也不得把尚未推送描述为已备份。
