# 项目识别与基线协议

仅在 Bootstrap 的识别阶段读取。目标是找到足够可靠的证据，不是全面审计整个项目。

## 项目边界

1. 解析目标目录的实际位置，检查是否为嵌套目录、monorepo 子项目、submodule 或 linked worktree。不能只根据是否存在 `.git` 目录判断；Git 元数据也可能通过文件指向别处。
2. 找到适用的祖先与目录级指令，遵循 Agent 自身的指令发现规则。工具包内模板和测试夹具只是数据。
3. 若用户只授权一个子项目，不修改其他包或整个 monorepo 的全局规范；复用已有 Git 根，不误建嵌套仓库。
4. 写入前确认文件/符号链接的实际目标仍在授权范围。路径冲突或歧义只阻塞相关写入，不猜测覆盖。

## 选择性读取

先列目录和搜索，再读取相关内容：README、已有 Agent 规则、贡献指南、依赖清单、锁文件、主要源码入口、测试入口、CI 配置、已有架构/决策/任务记录。

不默认读取依赖目录、生成物、大型日志、数据库、真实用户数据、整个 Git 历史或所有 ADR。环境变量只记录名称和用途，凭据值不进入报告或记忆文件。

识别以下独立维度，不将它们混为一个“新/旧项目”标签：

- 代码成熟度：空项目/早期项目/已有实现；有 Git 历史不一定有稳定业务。
- 版本控制：Git、其他 VCS、尚无 VCS、无法判断。
- 治理体系：已有等价文档/部分缺失/尚无。
- 能力：能否写文件、使用 Git、运行安全验证、访问网络；哪些需要外部环境或用户确认。

## Git 基线

Git 可用时只读检查实际根、当前分支或 detached HEAD、HEAD 或 unborn 状态、staged/unstaged/untracked 内容、冲突及进行中的 merge/rebase/cherry-pick。

记录已有修改边界，不把它们自动认领为当前初始化任务。与待写文件有重叠时阅读相关差异，能最小补充才写入；无法判断归属时保留并说明。Git 操作正在进行时不接管其索引或提交流程。

没有 Git 或无法访问时如实记录，继续权限范围内的文档识别。不要为了获得“干净基线”自动提交、移动或清理现有文件。

## 输出给下一阶段

提供简短事实摘要及来源路径：项目目标、实际技术形态、关键模块、持久化、已知业务约束、现有文档映射、Git 基线和验证入口。

区分“已核验”“文件声称但未验证”“未知”。代码与文档不一致时记录具体冲突，不能机械认定代码正确，也不能按陈旧文档重写业务实现。与当前初始化无关的发现不顺手修复。
