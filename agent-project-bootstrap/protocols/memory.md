# 项目记忆生成协议

识别完成后读取。原则：保留项目既有组织方式，新增最少且足够的独立长期记忆。

## 输出映射

相对于工具包 `templates/` 的模板路径，默认对应目标项目中去掉 `.template` 后缀的路径；`docs/tasks/TASK.md.template` 是例外，仅在需要实际任务时生成 `TASK-<id>-<slug>.md`。

已有等价文件优先复用，将实际路径记录到项目策略并修改入口引用。不要为了符合模板目录树移动大量既有文档；不要同时维护两份相同规则。

小项目可把架构摘要合入上下文、把工作/Git 协议合入同一协作文档、把无记录的任务/决策导航合为索引章节。映射需定位实际文件及章节，所有入口和文内引用同步调整；无需保留重复空文件。合并只改变组织方式，不能删减下述义务；项目扩大后仅在确有需要时拆分并更新映射。

| 输出职责 | 默认路径 | 适配要求 |
| --- | --- | --- |
| Agent 常驻规则 | `AGENTS.md` | 短入口，不复制全部协议；保留既有有效规则 |
| 项目 Current State | `PROJECT_CONTEXT.md` | 目标、形态、关键约束和导航；不做任务日志 |
| 人的使用入口 | `README.md` | 已有文件最小补充链接；不重写现有产品说明 |
| 当前架构 | `docs/architecture.md` | 只写实际模块与数据流；空项目写尚未形成 |
| 有效策略 | `docs/agent/policy.md` | 填实策略、路径、来源与版本，不能自授权限 |
| 后续工作协议 | `docs/agent/workflow.md` | 任务、验证、文档维护和交接 |
| 后续 Git 协议 | `docs/agent/git.md` | 归属、提交、同步与并行边界 |
| 任务索引 | `docs/tasks/README.md` | 无任务时为空，不建立虚假示例任务 |
| 决策索引 | `docs/decisions/README.md` | 无真实决策时不创建 ADR |

## 内容与更新规则

- 模板按目标项目改写，不是整目录盲目复制。替换所有 `{{...}}` 适配点；已有文件合并后仍要核对引用。
- 已有文件（包括未跟踪文件）先保留与本次写入有关的原文/差异用于核对，再定位缺项作插入或局部修改；不得先用整份模板覆盖、再尝试恢复用户段落。写后比对原有规则与标记，不能仅以文件仍存在或一个标记保留判断内容完整。
- 分步生成，先建立实际路径映射，再写入口引用。中断后从已有内容核对和补缺，不清空重建。
- 小项目可以很短；未知信息写明未知，不硬选技术栈、不虚构模块、测试、失败经历或开发历史。
- 当前上下文仅摘要长期有效的未解决约束；具体任务进度放 Task。架构记录检出版本的当前结构，不自动代表生产部署。
- 长期理由只在真实重要决策形成后写 ADR。将证据与推断分开，提出的建议不能写成已采纳决定。
- Task 保存必要且脱敏的需求摘要、恢复步骤和验证证据，不复制完整聊天或原始秘密。

## 策略应用

用户与项目既有明确配置优先；没有约定时使用策略模板的默认值，并报告实际采用值。对于操作范围未确认的远端选项，仅保存待确认，不自动建立远端或上传。

不要求用户回答整张配置表。缺失信息只影响相关动作；例如邮箱缺失不阻碍文档生成，无法观看 UI 不阻碍记录其验收缺口。

TASK_TRACKING_POLICY=disabled 时不生成真实 Task 或活动表，可保留注明停用的任务导航章节；既有任务和活动表原样保留，不为初始化刷新旧进度。其他通用规则仍落入长期文档，保留将来启用跟踪所需的最低规范。

## 不可裁剪的最低语义

以下约束必须落入目标项目实际生成或复用的长期文档，位置可变化，说明和示例可缩短。任务相关要求受有效 TASK_TRACKING_POLICY 约束，但不能因暂时无任务删除未来启用时的规则。

任务、策略和 Git 模板的规范正文默认保留；精简优先合并职责、删除重复解释和不适用示例。需要改写规范正文时，逐项与模板及下表对照，发现缺义务就从模板补回，不用一句“遵循策略”替代具体禁止、核对或恢复要求。已覆盖的规则在原段落补缺，不重复追加整套规范。

| 语义 | 生成结果必须保留 |
| --- | --- |
| 入口与职责 | 入口、上下文、策略及任务路径可定位；按需加载；合并文档有明确路径/章节映射 |
| 策略条件 | always/adaptive/disabled 的跟踪行为，提交/恢复提交/远端禁用的优先级，关闭能力的交接限制 |
| 任务身份与状态 | 沿用 ID；无外部 ID 时采用 TASK-日期-12 位随机十六进制并查冲突；六种标准状态；带时区更新时间；阻碍单列 |
| 任务最小记录 | 需求与澄清、范围及完成标准、基线与 staged/unstaged/untracked 边界、分支与依赖、核验快照、验证证据/缺口、阻碍/下一步、代码取得与环境恢复/结果限制 |
| 工作区保护 | 核对真实文件和 Git；保留用户已有内容；普通任务混合归属无法分离时不自动提交，明确项目快照请求可覆盖原有修改；单工作区单写入者 |
| Git 与敏感边界 | 写操作按策略；按请求推送默认保存整个项目可纳入 Git 的当前状态，不按任务筛选，不以测试/人工验收为备份门槛；必要的目标/分支与凭据保护检查，已检查并推送历史不重复扫描；失败或分叉保留本地快照，不强推、不伪造身份、不绕过 hook，不把秘密写入记忆 |
| 恢复与落盘 | 接手重要修改前简述目标、标准、进度、验证缺口、用户修改边界及快照偏差；启用跟踪时重要阶段保存；不保证崩溃前收尾 |
| 验证与事实 | 事实/推断/未知分开；证据绑定检查范围、版本和环境，行为改变后旧证据不自动延续；未运行不写通过 |
| 交付与授权 | 文档保存、本地代码保存、其他电脑可取得分别说明；实际目标、分支、内容、任务/阶段及副作用限定授权，历史授权不自行延伸 |
| 生命周期与维护 | done 按完成标准判断；任务先更新、活动索引随后同步，完成/取消后删活动行并核对 ID 不在活动表、文件仍在原路径，仅改行状态不算移除；仅更新受影响文档，不虚构 ADR/历史 |

“任务最小记录”中的关键依据、假设和失败尝试只在有内容时记录，不为满足格式编造。字段可合并，语义不可遗漏；已关闭跟踪时无需建立任务文件或维护活动表，仍保留通用保护、验证和交付边界。

## 重复执行与升级

已有相同版本也要核对关键文件，但不重复追加规则、任务或 ADR。已有策略不得因重跑被重置为默认值。

发现旧版本时先列出缺项或必要变更；在当前授权范围内做最小补充。涉及改变既有行为的升级需用户明确要求，不能借补缺扩大提交/上传权限。版本记录在生成的项目策略中，无需另建锁文件或后台机制。

## 生成完成检查

目标入口能定位实际文件，目标规则不依赖工具包或私有 Session，所有持久知识随目标项目取得。来源版本与固定提交可记录在项目策略中供追溯，但不得作为日常必读链接。不要把工具包自身整包作为目标项目的默认必读内容。

- 对照最低语义表逐项指出实际目标路径/章节及结果；缺失则先补齐可安全补充的内容，既有规则冲突时只阻塞相关项并说明。
- 核对有效策略在入口、workflow、Git 与任务索引中的条件一致；disabled 不被无条件义务覆盖，不静默改为默认值。
- 检查实际生成文档的链接、适配点、来源独立性与已有修改保护；真实任务存在时同时检查其最小字段和活动索引，无任务时只检查未来规则。
- 报告常规启动需要读取的实际文件/章节及其文本规模；字数/字节是规模指标，不等于 token 数。无需每次会话重新测量，不预先宣称节省比例。
- 分别报告文档检查、提交、同步及未知项。文件已存在而语义尚未核验不算完成；失败后保留已完成内容，重跑只补缺。

不默认生成所有平台的 Skill/Agent 适配文件；已明确知道所用工具需要时才做薄入口，内容指向共享规则。无法证实自动加载时明确要求后续 Agent 主动读取项目入口。
