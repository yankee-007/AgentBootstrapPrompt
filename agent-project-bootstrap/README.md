# Agent 项目启动协议 v0.4.0

用于让首个 Coding Agent 为软件项目建立“项目记忆与协作体系”。通过 GitHub 入口交付，适用于新项目和已有项目；仍需结合真实项目试用与迭代。

## 直接提供 GitHub 入口

无需手动下载工具包。让具备网络读取与目标项目写入能力的 Agent 执行下面的指令，并替换目标路径：

```text
请读取并执行 https://raw.githubusercontent.com/yankee-007/AgentBootstrapPrompt/main/agent-project-bootstrap/BOOTSTRAP.md ，目标项目为 <目标项目路径>。
先将入口的 main 解析为完整 commit SHA，重新读取固定提交的入口，所有协议和模板均从该提交获取。
按入口要求初始化项目记忆与协作体系，保留既有规范和未提交修改。
读取公开工具包不代表允许上传目标项目；完成初始化后停止，不开始业务开发。
```

也可以提供入口的 GitHub 文件页或固定提交永久链接。`main` 便于获得当前版本；一次执行必须固定 SHA，不能混用随时变化的文件。Agent 可按需远程读取或自行保存临时副本，无需在目标项目中永久保存工具包。

此工具包仅通过 GitHub 交付，不生成或维护离线 ZIP。Agent 可按需缓存同一固定提交的文件；网络或读取能力不足时报告具体阻碍，不要求用户另行提供离线包。此包不是需要安装的 Skill，也不会自动触发。不能修改目标文件的纯聊天工具无法直接执行初始化。

## 默认行为与边界

- 只建立或补充文档、项目记忆、必要的 `.gitignore` 与本地 Git；不修改业务代码。
- 已有同等文档优先复用，已有文件不整份覆盖；重复执行按补缺处理。
- 小项目可合并职责并记录路径/章节；必须保留任务、保护、策略、验证和交付的最低语义，收尾检查实际生成结果。
- 复杂任务才创建任务记录；空项目不虚构架构、决策或历史。
- 初始化后的独立修改任务默认先建立分支与 worktree，即使只有一个 Session；补充消息、修正和接力沿用原任务，讨论/查询通常不建。main 或既有集成分支只接收成果，由一个执行者串行 squash，满足集成条件后再收尾清理。
- 归属明确、验证完成且有真实提交身份时，可以创建本地初始化提交。
- 远端创建和上传需已确认的目标与范围；没有授权时保留本地结果，不妨碍完成其他初始化工作。
- 日常推送默认采用 `on-request`：用户要求推送时保存整个项目可纳入 Git 的当前状态，包括已有修改和未完成内容，不以测试或人工验收为备份门槛；沿用已确认目标，保留必要的凭据保护。已有项目策略优先，不自动上传。
- 不自动安装依赖、运行未知项目脚本、生成 SSH 密钥、调整全局 Git 配置或建立外部服务。

这些默认值可被明确的项目约定或用户指示调整；Agent 必须先识别实际适用的规则。

## 后续使用

目标项目的 `AGENTS.md` 是后续 Agent 的入口，详细规则按需加载。不会自动读取该文件的工具，可以显式要求“先阅读目标项目的 AGENTS.md”，或使用项目已有的入口适配。

初始化后，目标项目应能脱离本工具包工作。换电脑时取得目标仓库和必要环境即可，无需重新运行 Bootstrap。明确需要修复或升级时再执行，并保留已有项目规则。

## 任务分支与 worktree 如何使用

worktree 是同一 Git 仓库的额外工作目录，各任务拥有自己的文件副本、检出状态与暂存区。例如任务 A 修改接力规则，任务 B 稍后开始补充并行规则；两者各用一个分支/worktree，可以修改同名文件的不同副本。主目录的 main 仅用于接收成果。分支本身不能隔离同目录里的文件写入。

独立任务从当时已确认的集成版本开始，通常不复制其他任务的未提交修改。B 独立完成时可以先集成，A 后完成时再结合最新主线处理差异；存在依赖则记录所需版本与集成顺序。一个 Session 可先后做多个任务，更换 Session 可接着做原任务，不必每条消息新建分支。

任务分支内可保存多个过程提交，默认 squash 后主线形成一个任务成果提交；对话结束不自动合并，未完成或待接受任务继续保留。集成后验证相关行为和项目记忆一致性，再核对已保存内容与依赖，清理本任务本地 worktree/分支；采用 squash 时不能仅依赖“已合并分支”列表，长期保留过程历史需另保留版本引用。

无需记录 main 正在开发的占用状态来决定是否分支，但集成操作必须串行。最轻量方式是指定一个集成执行者；若允许多个 Session 自行集成，需另有可验证的互斥方式。Markdown 状态、Owner、超时和 `git worktree lock` 不提供文件写入互斥。数据库、端口、缓存和生成产物也需协调。

该流程是后续任务默认值，不在 Bootstrap 中自动创建业务任务。初始化可在指定工作区由一个写入者完成；已有项目的分支/集成策略优先，无 Git、无提交基线或禁用策略时明确限制。轻量任务仍可不建 Task 文件，工作区隔离与文档跟踪是不同条件。

多 worktree 备份按请求协调各任务快照和已授权分支，未完成内容留在任务分支；推送 main 不代表其他任务都已远端备份，不为备份提前集成。详细执行与边界随目标项目生成的 Git/工作协议取得，不需要日常重读本工具包。

## 文件与版本

- [BOOTSTRAP.md](BOOTSTRAP.md)：唯一 Agent 执行入口与文件清单。
- [来源与读取协议](protocols/source.md)：远程固定版本、路径解析与本地降级。
- [识别协议](protocols/discovery.md)：界定目标和现有工作边界。
- [记忆生成协议](protocols/memory.md)：模板适配与文件职责。
- [初始化 Git 协议](protocols/git.md)：本地 Git 和可选远端操作。
- [变更与升级说明](CHANGELOG.md)：版本差异、固定来源和最小升级方式。
- `templates/`：目标项目模板；`.md.template` 后缀用于避免被误识别为活动指令。

v0.4.0 没有程序化安装器、后台守护、分布式锁或自动合并器。任务隔离、集成和清理由 Agent 按生成的协议执行，不会因文件存在而自动运行；不保证突然中断前完成收尾。验证结果以交付说明为准，不将远程获取或静态检查视为跨 Agent 兼容性认证。
